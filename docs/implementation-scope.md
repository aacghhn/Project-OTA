# 무엇부터 어디까지 만들 것인가?

고객과 파트너가 사용할 수 있는 작은 예약 서비스를 만들고, 그 안에서 발생하는 정합성·실패 복구·성능 문제를 검증한다. 숙박업의 세부 정책은 현재 기능에 필요한 만큼만 도입한다. 문제 발견의 네 축을 모두 구현해야 하는 것은 아니다.

## 무엇부터 만들 것인가

파트너가 직접 상품을 관리하는 메인 OTA와 PG 연동부터 시작하는 순서를 후보로 둔다. 아래 순서는 고정된 계획이 아니며, **즉시 결제와 나중에 결제를 모두 지원한다는 방향은 유지한다.**

1. **상품 관리와 예약의 기본 흐름:** 파트너가 숙소·객실·요금제와 날짜별 가격·수량을 관리하고, 고객이 조건에 맞는 상품을 조회해 예약을 요청할 수 있게 한다. 여러 숙박일의 수량 확보와 동시 요청을 다룬다.
2. **즉시 결제와 취소·환불:** PG 시뮬레이터를 연결해 결제와 예약 확정을 이어 붙인다. 임시 확보 만료, 결제 결과 불명, 중복 요청, 취소 후 환불 미완료를 검증한다.
3. **나중에 결제:** 확정 예약을 유지하다 지정일에 결제하는 흐름을 추가한다. 예정 결제의 중복 실행과 고객 취소의 경쟁을 검증한다. 실패 후 유예·재시도·취소 정책은 이 단계에서 필요한 만큼 정한다.

각 단계에는 고객과 파트너가 결과를 확인할 수 있는 서비스 동작도 포함한다.

## 초기에는 어디까지 다룰 것인가

- **상품:** 국내 숙소의 원화 객실박을 판매한다. 객실 유형의 여러 요금제가 날짜별 수량을 공유한다. 개별 호실 배정과 인원별 추가 요금은 제공하지 않는다.
- **액터:** 파트너와 고객을 기본으로 한다. OTA 운영자 기능은 옵션이며, 운영자 화면이 없어도 실패 기록과 복구는 필요하다.
- **예약 이후:** 예약 이행, 즉시·나중 결제, 예약 전체 취소와 환불을 다룬다. 취소 정책은 무료 취소 기한과 환불 불가 같은 적은 수의 유형으로 시작한다.
- **대표 예외:** 결제 실패·결과 불명, 취소 후 환불 미완료, 숙소의 제공 불가를 다룬다. 제공 불가는 사유 기록과 취소·환불까지로 제한한다.
- **서비스 기반:** 고객과 파트너의 접근 권한, 입력 검증, 오류 안내, 기본적인 로그와 테스트를 해당 기능과 함께 구현한다.

부분 취소·예약 변경, 사유별 수수료 면제 심사, 노쇼 전용 절차, 대체 숙소 알선과 추가 보상·정산은 초기 범위에서 제외한다. 다중 통화와 복잡한 판매 제한·요금 정책의 확장은 필요해질 때 판단한다.

## 이후 무엇을 추가할 것인가

- **CM 연동 — 후보:** 외부 재고 갱신과 내부 예약의 조정을 검증할 때 추가한다. 예약 전달·재시도와 외부 상태 대조도 함께 다룬다.
- **검색 성능 — 후보:** 외부 연동과 별개로 진행할 수 있다. 조회 구현뿐 아니라 데이터 생성·부하 구성·측정과 예약 시 재검증까지 포함한다.
- **그 밖의 연동 — 미정:** PMS의 별도 구현, 외부 OTA의 역할, iCalendar와 OTA 제휴형 지원 여부·순서는 필요성을 확인한 뒤 정한다. 모든 외부 시스템을 먼저 만들지는 않는다.

메시징·캐시·별도 브로커는 필요한 보장과 병목이 드러났을 때 선택한다. 도구나 시스템을 추가하는 것 자체를 다음 단계의 목표로 삼지 않는다.

## 한 단계의 범위를 마무리하는 기준

- 선택한 기능을 고객·파트너 관점에서 실행하고 결과를 확인할 수 있다.
- 핵심 실패나 경쟁 상황을 재현하고, 제공하는 보장과 남은 한계를 설명할 수 있다.
- 중요한 설계 판단과 검증 결과를 남긴다. 미정 경로는 의도적 미구현으로 드러내고 완료한 기능과 구분한다.

다음 기능은 새로운 문제를 검증하거나 현재 흐름을 완성하는 데 필요할 때 추가한다.
